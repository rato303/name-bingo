# 要件定義書 - 名前ビンゴ Webアプリケーション

## 1. プロジェクト概要

本プロジェクトは、AWSの各種サービスとモダンな開発技術を組み合わせ、参加者とホストがリアルタイムで楽しめる名前ビンゴのWebアプリケーションを開発するものです。開発はAI駆動開発で進め、GeminiCLIがプロジェクト管理とアーキテクチャ設計を、ClaudeCodeが実際のコーディングを担当します。

---

## 2. システム要件

### 2.1. 機能要件

* **ゲームルーム機能**: ホストがゲームルームを作成、参加者名簿の登録、およびゲーム開始を宣言できる。
* **ビンゴカード機能**: 参加者は登録された名前からビンゴカードを生成する。フリーマスはなし。
* **ゲーム進行機能**: ホストが名前の抽選を行うと、その結果は参加者全員にリアルタイムで通知される。ビンゴカードの状態も同時に更新される。
* **状態通知機能**:
    * **リーチ通知**: あと1マスでビンゴとなる「リーチ」状態の場合、ホストと参加者全員に通知される。
    * **ビンゴ通知**: ビンゴ達成者が現れた場合、ホストと参加者全員に通知される。
* **ホスト向け機能**: ホストは、参加者ごとのビンゴカード作成状況を確認できる。
* **再参加機能**: ゲストは、ゲームから離脱しても**プレイヤー名とゲームルームID**を用いて、ゲームの途中から再参加できる。

### 2.2. 非機能要件

* **ログイン機能**: ユーザー認証機能は実装しない。
* **ユニーク性**: 同一ゲームルーム内では、プレイヤー名は一意とする。
* **リアルタイム性**: ゲームの進行状況は、WebSocketを利用してリアルタイムで同期される。
* **想定利用者数**: 同時に50人程度の利用を想定する。

## 3. 技術スタック・システム構成

### 3.1. 技術スタック

* **開発言語**: **TypeScript** (バックエンド・フロントエンド両方)
* **フロントエンド**: **Next.js** と **Chakra UI** を使用し、ポップでインタラクティブなUIを構築する。
* **バックエンド**: Amazon API Gateway (WebSocket API含む), AWS Lambda (サーバーレス)
* **データベース**: Amazon DynamoDB (NoSQL)
* **インフラストラクチャ**: **Terraform** を使用し、AWSリソースをIaC（Infrastructure as Code）で管理する。複数リージョンや開発・本番環境の切り替えに対応できる構成とする。

### 3.2. システム構成

* **クライアント**: Next.jsとChakra UIで構築されたフロントエンドは、AWS Amplifyでホスティングされる。
* **API**: Amazon API Gatewayが、クライアントからのリクエストとWebSocket通信を担う。
* **バックエンド**: API Gatewayのトリガーで実行されるAWS Lambdaが、TypeScriptで書かれたゲームロジックを処理する。
* **データベース**: DynamoDBに、ゲームの状態、参加者、ビンゴカードなどの情報が保存される。
* **インフラ**: Terraformを使用して、これらのAWSリソースをコードで管理・デプロイする。

## 4. 開発手法

* **アーキテクチャ**: ドメイン駆動設計（**DDD**）の考え方に基づき、ビジネスロジックを中心に据えた設計を行う。
* **テスト**: コードレクセレンス原則に基づき、テスト駆動開発（**TDD**）を必須で実施する。TDDの実践は、t-wada氏が推奨する進め方に準拠する。
* **リファクタリング**: プロジェクトを通して継続的なリファクタリングを実施する。手法は、Martin Fowler氏が推奨する方法に準拠する。
* **コードレビュー**: プルリクエストベースでのコードレビューを必須とし、コード品質の維持に努める。
